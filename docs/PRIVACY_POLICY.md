# Access AI Privacy Policy

**Effective date:** September 5, 2026

Access AI is an accessibility-focused application and research project developed by Palmetto Ridge Holdings LLC, operating through Palmetto Ridge Media Group. This Privacy Policy explains how Access AI handles information when you use the public website, the Streamlit proof of concept, and future native mobile versions of Access AI.

Privacy questions may be sent to **founder@access-ai.tech**.

## 1. Information Access AI may handle

Depending on which features you choose to use, Access AI may process:

- **Text you submit**, including questions, prompts, optional image questions, and conversation content.
- **Images you choose to capture or upload** for reading, scene description, object identification, or related visual assistance.
- **Voice recordings you choose to make** and transcripts generated from those recordings.
- **Accessibility preferences**, such as vision profile, interaction preference, screen-reader/device selection, answer style, and speech preferences.
- **Technical and usage information** generated by hosting, analytics, browser, or device services, such as IP address, browser/device information, timestamps, and page or feature usage.

Access AI does not currently require a user account in the public prototype.

## 2. How information is used

Information is used only as needed to provide, improve, secure, and evaluate Access AI, including to:

- answer user questions;
- analyze user-selected images;
- transcribe user-selected voice recordings;
- generate spoken responses;
- remember accessibility preferences during a session or, in native mobile builds, on the device;
- diagnose failures and protect the service from misuse;
- understand basic website usage and improve usability and accessibility.

Access AI is not designed to sell personal information or use user content for targeted advertising.

## 3. AI and service providers

The current proof of concept uses OpenAI API services for AI responses, image analysis, transcription, generated speech, and optional web search. When you use those features, the text, image, audio, search query, or related context needed to complete the request is transmitted to OpenAI for processing. Web-search results may originate from third-party websites.

Fixed onboarding prompts and the **Repeat last answer** action use the browser's speech-synthesis interface rather than the OpenAI API. Depending on the browser, operating system, installed speech engine, and device settings, speech synthesis may be handled on the device or by that platform's speech service.

The public proof of concept is hosted using Streamlit Community Cloud. The public website is hosted using third-party web infrastructure. The production-ready replacement website package in this repository does not include Google Analytics or another first-party analytics tag. Hosting providers may still generate ordinary security and access logs. If analytics is enabled later, this policy will be updated before that collection begins.

These providers process information under their own contractual terms, privacy practices, and security controls. Access AI does not control every aspect of a third-party provider's infrastructure.

## 4. Storage and retention

The current Streamlit prototype does not intentionally create long-term user profiles or a project-controlled permanent conversation database.

- Conversation content and accessibility preferences are held in Streamlit session state while the session is active. They are not durable account preferences and can be lost when the session ends or resets.
- Temporary audio files created for transcription are deleted by the application after the transcription request completes.
- Camera images are sent for analysis when the user activates image analysis and are not intentionally written by the application to a permanent local image archive.
- The separate native Android milestone is planned to store accessibility preferences locally on the user's device using Android DataStore. It is not planned to cloud-sync those preferences in the initial milestone.

The proof of concept sends Responses API requests with storage disabled. This prevents the application from opting into Responses API application-state storage, but it does not eliminate provider processing or all provider logs. OpenAI may retain abuse-monitoring logs for up to 30 days by default unless a different approved data-control configuration applies, and exceptional legal or safety retention may apply under the provider's terms.

Hosting security and access logs may be retained according to the hosting provider's settings and policies.

## 5. Camera and microphone access

Camera and microphone access are optional and are used only when the user chooses features that require them.

- Camera access supports image-based assistance such as reading text, describing a scene, or inspecting an object.
- Microphone access supports recording a spoken question for transcription.

Denying camera or microphone permission does not prevent use of text-based features.

## 6. Accessibility-related information

Access AI may process accessibility preferences because they are necessary to personalize how the application presents information and communicates with the user. These preferences are used to support accessibility functions and are not used for advertising.

Users should avoid submitting unnecessary highly sensitive information when a task can be completed without it.

## 7. Security

Access AI is designed to use encrypted network connections for production web and API traffic and to keep service credentials out of client-side source code and public repositories.

No system can guarantee absolute security. Access AI will continue to review dependency, credential, logging, and data-handling practices as the product develops.

## 8. Children

Access AI is not currently directed to children under 13, and the project does not knowingly seek to collect personal information from children under 13. If a future version is designed for use by children, the privacy model and required parental or guardian protections will be reviewed before release.

## 9. Your choices and deletion requests

You may choose not to use camera, microphone, or AI-enabled features.

Because the current public prototype does not create user accounts or a persistent user-content database, there may be no account record for Access AI itself to delete. For questions about information that may have been retained in project-controlled systems, contact **founder@access-ai.tech**.

If future versions add accounts, cloud history, or persistent user profiles, Access AI will provide appropriate access and deletion controls before those features are released.

## 10. Safety and sensitive use

Access AI is assistive software and is not a guaranteed navigation, medical, emergency, legal, financial, or safety system. AI output may be incomplete or incorrect. Users should independently verify high-risk information and should not rely on Access AI as the sole source for safety-critical decisions.

## 11. Changes to this policy

This policy may be updated as Access AI moves from proof of concept to native mobile and smart-glasses integrations. Material changes to data collection, storage, sharing, or account behavior will be reflected in this policy before the affected feature is broadly released.
